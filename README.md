# 태양광 자산진단·유지보수 플랫폼

- 상태: 계약 전 준비 + 로컬 전체 데모
- 작성일: 2026-08-25
- 최종 수정일: 2026-09-04
- 주의: 이 문서는 계약 및 요구사항 확정 전 검토 자료다. 구현 완료, 견적 확정 또는 납품 약속을 뜻하지 않는다.

`solar-asset-care`는 기존 홈페이지·ERP와 분리된 독립 신규 시스템이다. 계약 전 준비 문서와 함께, 전체 업무 흐름을 체험하는 온라인·로컬 데모와 독립 Supabase 프로젝트의 기본 구조를 관리한다. 현재 온라인 주소는 공개 데모이며, 상용 운영이나 실제 고객 자료 수용 단계는 아니다.

## 현재 데모

- 온라인 공개 데모: <https://solar-asset-care-demo.kimminho0914.chatgpt.site>

[`demo-site/`](demo-site/)에는 다음 흐름이 연결돼 있다.

- 운영 대시보드와 새 검사 접수
- 검사 목록, 설비·고객·협력업체 기준정보
- 촬영 파일 접수와 일사량·풍속·각도·거리·개인정보 마스킹 유효성 검사
- JPG·PNG 열화상 업로드와 비AI 상대 고온·저온 후보 분석
- 이상유형·Delta T 참고값 표시와 전문가 후보 확정·기각
- 기대발전량·PR·발전손실·수익·회수기간의 결정론적 계산
- 보고서 미리보기·승인, A4 PDF 저장과 고객 전용 화면
- 업체 3곳 견적 비교·선택·수수료 계산, 유지보수 후속관리
- 고객 설비 등록, 고지서 간이진단, 마이페이지와 승인된 FAQ 범위의 안내 데모
- 계산·촬영 기준값 편집과 설정 판본 표시
- 운영자·전문가·고객 역할 전환

열화상 데모는 일반 이미지의 색상 분포를 비교하므로 실제 섭씨 온도나 고장 확정값을 만들지 않는다. 카메라별 방사온도 원본 파서는 샘플 확보 후 같은 분석 계층에 연결한다.

### 로컬 실행

```bash
cd demo-site
npm install
cp .env.example .env.local
npm run dev
```

실제 연결 정보는 `.env.local`에만 두며 GitHub에는 포함하지 않는다.

## 1. 확인된 내용과 방향

사용자 설명과 「부천에너지이음 MVP 개발사 미팅」 자료에서 확인된 제품 흐름은 다음과 같다.

1. 고객사와 발전소의 검사를 접수하고 촬영 일정·설비 정보를 준비한다.
2. 열화상·가시광 원본과 촬영 정보를 변경 없이 보존한다.
3. 자동 분석은 온도 이상 또는 고장 의심 후보를 표시해 전문가의 판단을 돕는다.
4. 전문가가 원본·분석 결과·설비 정보를 함께 검토하고 최종 진단과 조치 권고를 확정한다.
5. 승인된 결과를 한글 고객용 PDF 보고서로 발행하고 개정 이력을 남긴다.
6. 고객은 자신의 보고서와 조치 권고를 확인한다.
7. 장기적으로 유지보수 요청, 견적, 작업, 조치 전후 결과까지 연결한다.

자동 분석이 최종 판정을 대신하거나 검토 없이 보고서를 발행하는 방식은 MVP 범위가 아니다. 회의자료가 제안한 실제 자료 3~5건의 전 과정 검수는 계약 시 파일 종류와 합격 기준을 확정해야 한다.

사용자 확인에 따르면 현재 다른 서비스는 `Cloudflare + GitHub + Supabase` 조합으로 운영하고 있다. 이 운영 경험은 신규 프로젝트의 초기 구성 후보로 활용하되, 이 프로젝트의 계정·데이터·배포는 기존 서비스와 분리한다.

## 2. 계약 전 기술 제안

제품의 핵심은 ‘AI 자동진단’이 아니라 `검사 접수 → 분석 보조 → 전문가 판정 → 보고서 발행 → 유지보수 연결`을 누락 없이 운영하는 업무 플랫폼으로 본다. 다중 고객 조직의 데이터를 분리할 수 있는 독립 SaaS 구조, 원본 불변 보존, 재시도에 안전한 비동기 처리, 역할별 승인과 감사 추적을 기본 설계 방향으로 제안한다.

초기 배포 후보는 GitHub를 소스와 변경 이력의 기준으로 삼고, Cloudflare를 프론트엔드·도메인·엣지 계층으로, Supabase를 인증·업무 데이터·비공개 파일 계층으로 사용하는 구성이다. Next.js·TypeScript 기반 웹, 별도 Python 이미지 처리 작업 서버, HTML/Chromium 기반 PDF 생성을 함께 검토한다. 모두 계약 전 제안이며 샘플 파일, 사용량, 예산과 운영 주체를 확인한 뒤 확정한다.

초기 고정비를 줄이기 위해 계약 전 시제품에서는 현재 운영 경험과 허용되는 무료/저비용 구간을 우선 활용한다. 실제 고객 원본을 받는 시점에는 일시정지, 파일 크기·저장량, 전송량, 자동 백업과 지원 수준을 다시 확인해 유료 전환 여부를 결정한다. 카페24 등 별도 호스팅은 국내 결제·지원, 특정 서버 운영 또는 계약상 요구가 확인될 때 다시 비교하며 초기 기본 구매 항목으로 두지 않는다.

특정 공급자를 영구 전제로 하지 않는다. 프론트엔드 배포물, 데이터베이스 변경 이력, 파일 목록·체크섬, 환경 설정과 작업 인터페이스를 분리해 Cloudflare, Supabase 또는 저장소를 나중에 바꾸더라도 업무 로직과 원본 이력을 최대한 유지할 수 있게 설계한다.

## 3. 추가 확인이 필요한 내용

계약 범위와 견적을 정하기 전에 최소한 다음 자료가 필요하다.

- 지원할 열화상 카메라 제조사·모델과 원본 샘플
- 방사온도 정보 포함 여부, 파일 형식, 촬영 조건과 이미지 매칭 기준
- 1회 검사당 파일 수·평균/최대 용량·동시 업로드 수
- 설비 연결 구조와 촬영 위치를 설비 위치에 연결하는 방식
- 기존 진단보고서 양식과 보고서 승인·정정·회수 절차
- 사용자 역할, 전문가 배정 방식, 처리 기한과 자격 기준
- 유지보수 업체 연결·견적·완료 처리 범위
- 고객사·발전소·동시 사용자 예상 규모와 데이터 보존 기준
- 인버터 제조사·모델·계정 소유자·데이터 접근 권한
- 기능별 계약 범위, 일정, 예산, 검수, 권리 귀속, 하자보수와 인계 조건
- 현재 사용하는 Cloudflare 서비스 종류, 계정·도메인 소유자와 배포 방식
- Supabase 조직·프로젝트의 소유권, 사용 플랜, 데이터 지역과 실제 고객 자료 수용 시점
- 이전이 필요한 조건, 허용 중단시간, 데이터 반출·복원 목표와 대체 운영 환경

## 5. 자료 출처와 한계

- 사용자 요청: 프로젝트 성격, 서비스 이해, 후보 범위와 기술 방향의 우선 근거다.
- 「부천에너지이음 MVP 개발사 미팅」(2026-08-24): 회의 목적, 필수 기능 묶음, 실제 자료 검수와 개발사 확인 항목의 참고 자료다. 승인된 요구사항서나 계약서가 아니다.
- 상위 프로젝트의 기존 Markdown: 확정/추정 구분, 출처·한계, 재현·검증, 멀티테넌시, 보안·백업, 변경 이력 원칙만 참고했다.

기존 시스템의 테이블명, 컬럼, API 주소, 고객 정보, 인증키, 실제 운영 전제는 이 프로젝트로 복사하지 않았다.
