# PDF 요구사항 대비 데모 일치도 점검

- 기준일: 2026-09-04
- 기준 문서: 「솔라이음 AI진단 플랫폼 개발」 PDF
- 점검 대상: `demo-site/`
- 해석 원칙: 화면에서 흐름을 시연할 수 있는지와 실제 운영 데이터·외부 서비스까지 연결됐는지를 구분한다.

## 결론

PDF가 제시한 관리자 화면 A-1~A-6과 고객 화면 C-1~C-5는 데모에서 모두 이동하고 핵심 상호작용을 시연할 수 있다. 따라서 **화면·업무 흐름 기준 11개 중 11개 대응**이다.

다만 이것은 상용 기능 100% 완료를 뜻하지 않는다. 현재는 비용이 발생하지 않는 샘플 데이터 모드이며 실제 Supabase 저장, 방사온도 원본 파서, Claude API, 고지서 OCR, 외부 업체 발송과 서버 PDF 보관은 후속 운영 연동 대상이다.

## PDF 계산식 반영

- 기대발전량: 설비용량 × 일평균 발전시간 × 365 × 연차 열화계수
- 성능비(PR): 실제발전량 ÷ 기대발전량
- 발전손실량: 기대발전량 - 실제발전량
- 수익·손실: 자가소비형 또는 발전사업형 단가를 구분해 계산
- 회수가능액: 손실금액 × 이상유형별 개선가능비율
- 투자회수기간: 예상 수리비 ÷ 연간 회수가능액

숫자 계산은 AI가 아닌 `demo-site/lib/solar-calculations.ts`의 결정론적 함수가 담당한다. 같은 입력과 같은 설정 판본이면 같은 결과가 나온다.

## 운영 연결 전에 반드시 남은 핵심

1. PDF가 요구하는 실제 자료 3건의 전 과정 검수: 등록 → 촬영 → 분석 → 전문가 확정 → 보고서 → 업체 견적 → 조치 이력.
2. 카메라 제조사·모델별 방사온도 원본 샘플과 온도 추출 방식 확정.
3. Supabase Auth·업무 데이터·비공개 파일을 화면에 연결하고 조직 간 접근 차단 회귀검사.
4. Claude와 OCR의 입력·출력·실패·재검수 기준, 비용 상한과 호출 기록 확정.
5. 보고서 판본·승인·회수와 업체 견적 발송·회신·수수료 정산을 실제 데이터로 연결.
6. 개인정보 마스킹, 보존·삭제, 백업·복원, 감사기록과 운영 모니터링 검증.

## 데모에서 의도적으로 하지 않는 일

- 실제 고객 파일과 개인정보 저장
- 실제 온도나 고장 확정값 생성
- 외부 업체에 메시지 발송
- 유료 AI·OCR 호출
- 상용 계약·결제·정산 처리

이 구분을 유지해야 데모가 PDF의 방향을 보여주면서도 구현 완료 또는 진단 정확도를 과장하지 않는다.
