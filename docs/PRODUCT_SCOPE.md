# 제품 범위

- 상태: 계약 전 준비 초안
- 작성일: 2026-08-25
- 주의: 이 문서는 계약 및 요구사항 확정 전 범위 검토 자료다. 기능 포함 여부, 성능, 일정과 비용은 계약 시 확정해야 한다.

## 1. 문서 목적

태양광 발전소의 열화상·가시광 검사 자료를 안전하게 관리하고, 자동 분석이 제시한 후보를 전문가가 검토해 고객용 보고서와 후속 유지보수로 연결하는 독립 시스템의 제품 경계를 정리한다.

## 2. 확인된 내용

### 2.1 해결하려는 문제

- 검사 접수, 대량 이미지, 설비 정보, 전문가 의견, 보고서와 후속 조치가 분리되면 누락과 최신본 혼동이 생길 수 있다.
- 자동 분석만으로는 촬영 조건, 설비 연결 구조와 현장 맥락을 충분히 반영하기 어렵다.
- 고객에게 제공할 결과에는 전문가의 최종 판단과 판정 근거, 권고 조치가 필요하다.
- 원본과 분석 파생물, 초안과 발행본을 구분하지 않으면 재현과 책임 추적이 어렵다.

### 2.2 제품 목표

1. 검사 1건의 접수부터 고객 보고서와 후속 조치까지 한 흐름으로 추적한다.
2. 원본 이미지와 촬영·설비 맥락을 함께 보존한다.
3. 자동 분석은 이상 후보와 판단 자료를 제공하고 최종 진단은 전문가가 담당한다.
4. 보고서의 초안, 검토, 승인, 발행과 개정 이력을 구분한다.
5. 고객은 자신의 발전소 자료만 안전하게 확인한다.
6. 향후 유지보수 업체 연결과 결과 확인까지 확장할 수 있게 한다.

### 2.3 주요 이용자 후보

- **운영 관리자**: 고객사·발전소·검사·일정·전문가·보고서 발행을 관리한다.
- **현장 촬영 담당자**: 촬영 조건과 원본 파일을 제출하고 누락을 보완한다.
- **진단 전문가**: 원본, 분석 후보와 설비 정보를 검토해 진단·근거·권고를 작성한다.
- **승인 담당자**: 보고서 발행 전 완전성·표현·승인 조건을 확인한다.
- **고객 사용자**: 본인 조직의 발전소 보고서와 권고·조치 현황을 본다.
- **유지보수 담당자/사업자**: 계약 범위에 포함될 경우 요청, 견적, 작업과 완료 증빙을 처리한다.

역할의 겸임 가능 여부와 실제 권한은 아직 확인되지 않았다.

## 3. 계약 전 기술 제안

### 3.1 MVP 핵심 범위 후보

#### A. 기준 정보와 검사 접수

- 고객사·발전소·담당자 관리
- 인버터, MPPT, 스트링, 모듈 등 설비 연결 구조의 개념적 관리
- 검사 요청, 일정, 촬영 담당자와 전문가 배정
- 촬영 위치·조건·동의 또는 필요한 증빙의 관리

#### B. 파일 접수와 품질 확인

- 열화상·가시광 원본 일괄 업로드
- 대용량 파일의 중단·재개, 재시도와 중복 방지
- 파일 형식·크기·체크섬·메타데이터 기록
- 원본, 화면용 미리보기, 분석 파생물의 구분
- 이미지 짝 자동 매칭 후보, 신뢰도 표시와 수동 수정

#### C. 분석 보조와 전문가 검토

- 온도 이상 또는 고장 의심 영역의 후보 표시
- 확대, 비교, 영역·점·주석 표시
- 분석 결과의 근거·신뢰도·실행 정보 표시
- 전문가 진단, 판정 근거, 코멘트와 조치 권고
- 전문가 수정 이력과 주요 동작 감사 기록

#### D. 보고서와 고객 제공

- 보고서 초안, 검토, 승인, 발행과 개정
- 한글 고객용 PDF 생성과 다운로드
- 고객별 발전소·보고서·조치 권고 조회
- 보고서 발행·정정·회수 알림 후보

#### E. 유지보수 후속 흐름

- 유지보수 요청, 담당/사업자 연결과 진행 상태
- 견적 또는 비용 자료 관리 범위 후보
- 조치 전·후 사진과 완료 결과
- 권고 항목과 실제 조치 결과의 연결

#### F. 운영 안전장치

- 역할별 권한, 조직별 데이터 격리와 비공개 파일 접근
- 데이터 내보내기, 보존, 백업·복원 계획
- 업로드·분석·알림·보고서 작업의 재시도와 중복 실행 안전성

### 3.2 장기 과제 또는 최초 MVP 제외 후보

- AI 단독 최종 고장 판정과 검토 없는 보고서 자동 발행
- 신규 AI 모델 학습을 전제로 한 고정밀 판독
- 여러 제조사 인버터 API의 동시 연동과 실시간 대규모 관제
- 열화상 이미지만으로 설비 위치를 자동 확정하는 기능
- 자동 예지 정비와 자동 유지보수 입찰
- 온라인 결제·자동 정산
- 네이티브 모바일 앱
- 정사영상·대규모 자동 모듈 인식 등 별도 영상측량 제품에 가까운 기능

### 3.3 MVP 성공 기준 후보

회의자료의 검수 방향을 바탕으로, 계약 시 선정한 실제 또는 비식별 시험 자료 3~5건에서 다음 흐름이 역할·권한에 맞게 끝나는 것을 후보 기준으로 제안한다.

`접수 → 원본 업로드 → 품질/짝 확인 → 이상 후보 표시 → 전문가 수정·확정 → 보고서 승인·발행 → 고객 다운로드 → 후속 조치 기록`

합격 조건에는 결과 화면뿐 아니라 원본 무결성, 개정 이력, 조직 간 접근 차단, 소스·계정·문서·백업 절차 인계를 포함할지 계약에서 명시해야 한다.

## 4. 추가 확인이 필요한 내용

### 4.1 범위 결정 질문

- MVP에 유지보수 사업자 화면과 견적 처리를 어디까지 포함할 것인가?
- 고객이 파일을 직접 올리는가, 운영자가 대신 접수하는가?
- 현장 촬영 일정과 동의·기상 정보는 필수 업무인가 참고 정보인가?
- 전문가와 승인 담당자는 분리되는가? 한 사람이 겸임할 수 있는가?
- 보고서 개정·회수 시 고객이 과거 발행본을 볼 수 있는가?
- 고객에게 분석 후보와 원본까지 보여줄 것인가, 승인된 보고서만 보여줄 것인가?
- 알림 채널과 발송 시점, 수신 거부/실패 처리는 어디까지 필요한가?

### 4.2 규모·성능 질문

- 고객사·발전소·동시 사용자 수와 월 검사 건수
- 검사 1건당 파일 수, 평균/최대 파일 크기와 총 용량
- 한 번에 올릴 파일 수, 허용 업로드 시간과 재개 보존 기간
- 분석 완료 목표 시간과 성수기 동시 작업 수
- 보고서 페이지 수, 이미지 해상도와 월 발행량
- 데이터 보존 기간과 예상 저장량 증가율

### 4.3 계약·인계 질문

- 필수/선택 기능별 공수·공급가액·부가세·월 운영비·유지보수비
- 일정, 단계별 지급, 지원기관 사전 승인과 선금보증 필요 여부
- 요구사항서, 화면설계, 아키텍처, 시험서, 운영 매뉴얼의 인계 범위
- 소스, 도메인, 저장소, 클라우드와 데이터 계정의 소유 주체
- 산출물 권리, 수정·2차 개발 권리, 하자보수 기간·범위·응답시간

회의자료의 예산 및 기관 심의 조건은 참고 정보이며 현재 유효한 규정과 계약 구조를 별도로 확인해야 한다.

## 5. 범위 변경 원칙

새 기능을 MVP에 추가하려면 사용자 가치, 필수 데이터, 권한, 실패 처리, 시험 자료, 수용 기준, 비용과 일정 영향을 함께 기록한다. 샘플이나 공식 API 문서 없이 이미지 형식·인버터 컬럼·상태값을 확정하지 않는다.
