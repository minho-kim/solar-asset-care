# 사용자 업무 흐름

- 상태: 계약 전 준비 초안
- 작성일: 2026-08-25
- 주의: 이 문서는 계약 및 요구사항 확정 전 업무 흐름 후보를 정리한 것이다. 실제 역할, 승인 순서와 상태 체계는 확정되지 않았다.

## 1. 확인된 내용

서비스의 중심 흐름은 `검사 접수 → 원본 관리 → 분석 보조 → 전문가 판정 → 보고서 발행 → 고객 확인 → 유지보수 후속 조치`다. 자동 분석은 전문가에게 후보를 제시하며, 최종 고장 판정과 보고서 승인은 사람이 담당한다.

## 2. 계약 전 기술 제안

### 2.1 전체 흐름

1. **검사 요청 접수:** 운영 관리자가 고객사, 발전소, 요청 목적, 희망 일정과 담당자를 확인한다. 필수 정보가 부족하면 접수 확정 전에 보완을 요청한다.
2. **설비·촬영 준비:** 발전소 설비 연결 구조, 촬영 위치 표기 방식, 카메라·촬영 조건과 필요한 동의를 준비한다.
3. **원본 제출:** 촬영 담당자가 열화상·가시광 원본과 촬영 정보를 올린다. 대용량 업로드는 중단 후 이어서 할 수 있어야 한다.
4. **접수 품질 확인:** 시스템이 형식, 손상 여부, 중복 가능성, 체크섬, 짝 누락과 메타데이터 부족을 확인해 보완 대상을 표시한다.
5. **이미지 짝과 위치 확인:** 자동 매칭 후보와 신뢰도를 보여주고 담당자가 잘못된 짝을 고치거나 미매칭으로 확정한다. 촬영 위치와 설비 위치 연결을 확인한다.
6. **분석 보조 실행:** 별도 작업이 원본 사본 또는 승인된 파생 입력을 이용해 온도 이상·고장 의심 영역 후보와 시각화 결과를 만든다. 실패·재시도·실행 버전을 추적한다.
7. **전문가 검토:** 전문가는 원본, 가시광 짝, 촬영 조건, 설비 정보와 분석 후보를 비교한다. 후보를 채택·수정·기각하고 최종 진단, 근거, 코멘트와 권고 조치를 작성한다.
8. **보고서 검토·발행:** 보고서 초안을 만들고 누락, 표현, 이미지·표, 승인 조건을 확인한다. 승인된 판본만 고객에게 발행한다.
9. **고객 확인:** 고객은 자신의 조직과 발전소에 발행된 보고서·권고를 조회하고 PDF를 내려받는다. 알림 여부는 계약에서 정한다.
10. **후속 조치:** 필요 시 유지보수 요청을 만들고 담당/사업자, 견적, 작업 일정, 전후 사진, 완료 결과를 기록한다.

### 2.2 역할별 흐름

#### 운영 관리자

- 고객사·발전소와 검사 요청의 중복 여부를 확인한다.
- 필요한 설비·촬영 정보와 파일 접수 상태를 확인한다.
- 전문가를 배정하고 처리 기한을 모니터링한다.
- 보고서 승인 조건을 확인하고 고객 공개 범위를 관리한다.
- 유지보수 요청과 미완료 권고를 추적한다.

#### 현장 촬영 담당자

- 현장·설비·촬영 묶음을 올바르게 선택한다.
- 촬영 시각, 장비, 거리·각도, 날씨·일사량 등 계약에서 정한 필수 조건을 기록한다.
- 원본 파일을 올리고 업로드·체크섬 완료를 확인한다.
- 누락된 가시광/열화상 짝이나 잘못된 위치 정보를 보완한다.

#### 진단 전문가

- 자신에게 배정된 검사와 처리 기한을 확인한다.
- 원본과 분석 파생물을 명확히 구분해 검토한다.
- 자동 후보를 그대로 확정하지 않고 촬영 품질·설비 맥락과 함께 판단한다.
- 최종 진단, 판정 근거, 불확실성, 조치 우선순위와 권고를 작성한다.
- 수정 사유를 남기고 승인 요청 전 필수 항목을 확인한다.

#### 승인 담당자

- 전문가 검토 완료, 필수 근거와 고객 표현을 확인한다.
- 보고서의 발전소·검사·이미지·진단 대응 관계를 확인한다.
- 수정 요청 또는 승인을 수행한다.
- 발행·개정·회수 시 고객 노출과 알림 정책을 따른다.

#### 고객 사용자

- 자신의 조직에 허용된 발전소만 조회한다.
- 발행된 최신 보고서와 허용된 과거 판본을 확인한다.
- 권고 조치와 진행 상황을 확인하거나 유지보수를 요청한다.
- 접근 권한이 없는 원본·다른 고객 자료에는 접근할 수 없어야 한다.

#### 유지보수 담당자/사업자

- 계약에서 허용된 요청과 필요한 진단 정보만 확인한다.
- 견적 또는 작업 계획을 제출하고 진행 상태를 갱신한다.
- 조치 전·후 사진과 완료 결과를 제출한다.
- 고객 승인·정산·자동 입찰은 별도 범위로 둔다.

### 2.3 예외 흐름

#### 업로드 중단 또는 중복

중단된 업로드는 같은 대상과 파일임을 검증해 이어서 처리한다. 동일 체크섬이 발견돼도 곧바로 삭제하지 않고 동일 파일의 재제출인지, 다른 검사에서 합법적으로 재사용된 파일인지 판단할 수 있게 표시한다.

#### 손상·지원하지 않는 파일

원본을 임의 변환해 정상 파일처럼 처리하지 않는다. 실패 이유와 원본 보존 여부를 알리고 재제출 또는 지원 가능성 확인으로 보낸다.

#### 이미지 짝 누락·오매칭

신뢰도가 낮거나 복수 후보가 있으면 자동 확정하지 않는다. 담당자가 짝을 수정·해제하고 그 이력을 남긴다. 짝이 없어도 전문가 검토가 가능한지는 계약에서 정한다.

#### 분석 실패·재실행

원본 접수 자체와 분석 작업 상태를 분리한다. 재실행은 기존 결과를 덮어쓰지 않고 어떤 실행 결과가 보고서 판단에 사용됐는지 추적할 수 있게 한다.

#### 전문가 의견 변경

승인 전 수정과 발행 후 정정을 구분한다. 누가, 언제, 무엇을, 왜 바꿨는지 확인할 수 있어야 한다.

#### 보고서 정정·회수

발행본을 무음으로 교체하지 않는다. 새 판본, 변경 사유, 승인자, 공개 시점과 고객 안내를 연결한다. 회수된 보고서의 열람 정책은 계약에서 정한다.

#### 유지보수 미완료

권고가 거절·보류·부분 완료되거나 외부 업체가 응답하지 않을 수 있다. 진단의 사실과 후속 업무의 진행 상태를 섞지 않고 사유와 다음 조치를 기록한다.

## 3. 추가 확인이 필요한 내용

- 역할별 사용자 수, 겸임 허용과 승인 분리 원칙
- 고객·현장 담당자·전문가 중 누가 파일과 설비 정보를 수정할 수 있는지
- 검사 취소, 재촬영, 일부 파일만 재제출하는 절차
- 전문가 배정 방식, 자격 검증, 처리 기한과 대체 배정
- 분석 후보의 유형·심각도·신뢰도 표현 방식
- 보고서 승인 단계, 전자서명/도장 필요 여부와 법적 효력 기대
- 개정·회수 시 과거 판본 보관 및 고객 열람 정책
- 유지보수 업체가 볼 수 있는 정보와 고객 동의 범위
- 견적 비교, 작업 승인, 완료 확인과 정산의 MVP 포함 범위
- 이메일·문자·앱 내 알림의 발송 주체와 실패 처리

## 4. 계약 시 시나리오로 고정할 항목

각 흐름은 ‘누가, 어떤 입력으로, 어떤 완료 결과를 얻으며, 실패 시 어디로 돌아가는지’를 실제 샘플 3~5건으로 확정한다. 화면 수나 모달 표시가 아니라 고객 보고서와 후속 기록이 올바른 권한·이력으로 완성되는지를 수용 기준으로 삼는다.
