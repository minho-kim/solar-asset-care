# 공개 배포 전 로그인·보안·오류 점검

- 기준일: 2026-09-05
- 대상: solar-asset-care 로컬 운영 화면과 독립 Supabase 프로젝트
- 상태: 공개배포 보류. 기존 공개 데모는 변경하지 않았다.
- 상세 구현·시험 범위: [현재 개발 현황](DEVELOPMENT_STATUS_2026-09-05.md)

## 현재 결론

관리자·전문가·의뢰인의 주요 업무 흐름을 실제 세션으로 시험했다. 파일 업로드, 전문가 수동 판정, 촬영조건·서버 계산, 검토·승인·PDF 보관·발행·의뢰인 다운로드를 확인했다. 이것은 합성 자료 기반 1건의 개발 시험이며, 요구서 전체 구현이나 실제 고객 3건 검수 완료가 아니다.

PDF 시험 과정에서 한글 OTF 글꼴 호환 문제를 찾아 정적 TrueType으로 교체했다. 생성 PDF를 실제 렌더링해 A4·최소 11pt·한글/온도 단위·잘림 여부를 확인했다.

임시 계정·조직·업무 데이터·시험 파일은 정리했다. 현재 관리자 계정과 기존 운영 조직은 변경하지 않았다. 최신 코드 검사 46개·실제 API 시험 88개를 통과했다. Chrome 390px·320px에서 세 역할의 인증서 검색/다운로드/공개/회수/정정, 사진 가림 저장/관리자 승인, 고객 보고서 읽기/PDF 다운로드를 따로 시험했다. 브라우저 파일 선택은 확장프로그램 권한에 막혀 미검증이며 실제 휴대폰·복수 선택·모바일 재개와 대표 원본 검수도 남아 있다.

### 저장소 캐시에서 발견한 추가 사항

회수 후 일반 파일 GET이 `CF-Cache-Status: HIT`로 계속 응답했다. `cacheControl: 0`만으로 해결되지 않는 것을 확인했다. 의뢰인의 직접 저장소 접근을 원천 차단하고 고객용 파일은 `private, no-store` 응답을 사용하는 사이트 API로 전달한다. API는 사용자를 확인하고 현재 보고서·보관본 권한을 검사한 뒤에만 서버 전용 파일 읽기를 수행한다. 앱 API, 직접 저장소, 다른 조직·의뢰인, 승인 전, 회수 후 접근 시험을 추가했다.

향후 호스트에는 서버 전용 `SUPABASE_SECRET_KEYS`와 `REPORT_ASSET_ORIGIN`을 공급해야 한다. 브라우저 코드나 공개 환경변수에 비밀 키를 넣지 않는다. 내부 직원의 기존 원본 서명 URL과 직원 권한 회수 후 캐시 처리는 별도 남은 검수다. 이미 내려받은 파일은 원격 회수할 수 없다.

## 공개 전에 남은 항목

1. 가입 확인·전문가/관리자 초대·비밀번호 재설정 메일의 실제 수신과 링크 만료·재사용·잘못된 주소 검사.
2. 실제 운영 도메인과 인증 복귀 주소 확정·연결. 운영 발신자/메일 서비스의 발송 제한·복구 절차 검증.
3. 관리자 MFA, 봇 방지와 유출 비밀번호 차단 검토. 유료 기능이나 플랜은 승인 없이 활성화하지 않는다.
4. 신규 사진 편집·복수 업로드 화면의 휴대폰 조작·키보드·오류 복구·HTML 인쇄 미리보기. 반응형 코드와 생성 PDF 검증을 휴대폰 실기 검수와 혼동하지 않는다.
5. 7MB 재개 시험 외에 50MB 경계·다수 동시 전송·임시 객체 자동 정리, 악성·변조 파일과 초대 재시도 제한.
6. 수동 마스킹·승인 사진·마커 연결은 구현했다. 실제 사진의 가림 품질, TIFF 미리보기, 카메라 원본별 온도 파서 검증은 남아 있다. 일반 색상 이미지로 실제 온도를 단정하지 않는다.
7. DB·Storage 백업 및 별도 환경 복원, 권한 회수·파일 보존·파기·오류 감시.
8. 승인된 대표 자료 3건으로 의뢰·검토·발행·견적 비교·선택·후속 조치까지 종단 검수.

원본 해시 기록만으로 제조사 온도 정확성·악성 파일 전체 검사까지 보장한다고 표현하지 않는다. 이번 일반 계정의 원본 변경·삭제 차단은 관리자 권한의 유지관리 도구나 별도 보존·삭제 정책까지 대체하지 않는다.
