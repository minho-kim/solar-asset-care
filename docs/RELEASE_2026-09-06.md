## 🔐 환경·인증 주소

Sites의 서버 비밀 설정에 `SUPABASE_SECRET_KEYS`를 추가했고 `REPORT_ASSET_ORIGIN`은 위 공개 사이트 origin으로 지정했다. 기존 공개 Supabase URL·publishable key·live 모드·한국시간 설정은 유지했다. 비밀값은 Git·문서·배포 파일에 넣지 않았다.

합성 계정의 인증 링크 검사에서 요청 주소와 무관하게 `http://localhost:3000`으로 돌아가는 문제를 재현했다. 해당 독립 Supabase 프로젝트의 `site_url`만 현재 공개 사이트의 `/`로, `uri_allow_list`만 공개 사이트의 `/`와 기존 `http://localhost:3000`, `http://localhost:3000/`로 수정했다. 다른 인증 설정 전체가 변경 전과 같은지 비교했다. 링크 생성 API는 메일을 발송하지 않으며 실제 수신 성공을 뜻하지 않는다.

SMTP가 연결되지 않았고 이메일 확인은 활성 상태다. 일반 고객의 가입 확인·초대·비밀번호 재설정 메일은 발신자/SMTP 연결과 실제 수신 검증 전까지 준비 미완료다. 이메일 확인을 끄지 않았다. [Supabase 기본 SMTP 제한](https://supabase.com/docs/guides/auth/auth-smtp)
