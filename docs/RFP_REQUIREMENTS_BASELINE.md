# PDF 과업지시서 기준 설계 베이스라인

> 이 문서는 요구사항 기준선이며 실시간 진척도 표가 아니다. 특히 14절의 구현 상태는 기준일 당시 기록이다. 최신 구현·검증·미구현 범위는 [개발 현황](DEVELOPMENT_STATUS_2026-09-05.md)에서 확인한다.

- 상태: 상대방 요구사항 기준 설계
- 기준일: 2026-09-04
- 원문: 「솔라이음 AI 진단 플랫폼 MVP 개발 과업지시서」(문서 표기일 2026-07-31)
- 적용 원칙: 사용자의 2026-09-04 지시에 따라 가능한 범위에서 이 PDF의 제품·기능·데이터·화면·검수 내용을 설계 기준으로 사용한다.

## 1. 기준의 범위

이 문서는 PDF에 흩어진 요구사항을 실제 개발에 사용할 수 있도록 하나의 설계 기준으로 묶는다. 제품 설계와 구현 우선순위는 이 문서를 따르며, 기술적으로 불확실한 항목은 삭제하지 않고 샘플 검증과 수동 대체 경로가 필요한 구현 게이트로 관리한다.

PDF와 별도 제출 요청서 사이의 문서 버전, 지급 조건, 제출 양식과 날짜 차이는 계약 행정 항목이다. 이 차이는 최종 계약 전에 확인하되 제품 설계 범위를 임의로 축소하는 근거로 사용하지 않는다. 서명된 계약서·최종 과업지시서가 나오면 그 문서가 최종 우선한다.

## 2. 제품 목표와 운영 원칙

제품은 열화상 드론 점검 자료를 바탕으로 다음 업무를 하나의 웹 서비스에서 연결한다.

1. 설비와 점검 자료 등록
2. 촬영 유효성 판정
3. 이상 후보 제시와 관리자 검수
4. 기대발전량·성능비·손실금액·회수기간 계산
5. 고객용 웹 리포트와 PDF 발행
6. 조치 항목별 업체 매칭·복수 견적 비교
7. 점검·견적·조치 이력 관리

AI는 후보 분류, 설명문 작성, 고지서 판독과 일반 문의 보조에 사용한다. 금액과 성능 수치는 결정론적 계산 엔진이 만들며, AI가 숫자를 임의 생성하지 않는다. 이상 후보는 관리자가 확정하기 전 고객에게 공개하지 않는다.

## 3. PDF 기준 6개 기능군

| 기능군 | 설계 기준 |
|---|---|
| 입력 | 관리자가 열화상·가시광 원본과 촬영일시, GPS, 일사량, 외기온, 풍속 등 점검 자료를 업로드한다. 고객의 설비 등록 사진과 점검 원본의 권한을 구분한다. |
| 분석 | 규칙 또는 AI가 이상 후보, 유형, 위치, Delta T와 신뢰도를 제시하고 관리자가 확정·수정·삭제한다. |
| 연산 | 기대발전량, 실발전량, 성능비, 손실량·손실금액, 기대수익, 회수가능액과 투자회수기간을 코드로 계산한다. |
| 출력 | 승인된 결과를 고객 웹 리포트와 PDF로 발행하며 이상 위치, 손실금액, 개선 제안과 자료 한계를 표시한다. |
| 연결 | 이상 유형을 업체 유형에 연결하고 업체 3곳에 견적을 요청해 금액·기간·평점을 비교·선택하며 수수료를 계산한다. |
| 관리 | 발전시간, 열화율, 단가, SMP, REC, 가중치, 개선가능비율, PR 구간과 Delta T 임계값을 관리자 화면에서 수정한다. |

설정값은 코드에 하드코딩하지 않는다. 보고서와 계산 결과에는 사용한 설정 판본과 기준일을 연결해 나중에 값이 바뀌어도 과거 결과를 재현할 수 있게 한다.

## 6. 열화상 유효성·이상 판정

### 6.1 촬영 유효성

- 면내 일사량 기본값은 600 W/m² 이상이며 미달 시 경고하고 리포트 발행을 차단한다.
- 풍속은 관리자 설정 기준을 초과하면 경고한다.
- 촬영 각도·거리는 점검자가 입력하고 관리자가 검수한다.
- 적용 기준, 입력 출처, 단위, 측정 시각과 관리자 예외 승인 여부를 기록한다.

일사량·풍속·각도·거리 기준은 관리자 설정으로 관리한다. 촬영 조건이 부족하면 분석 결과를 만들 수 있더라도 고객 발행 상태로 전환하지 않는다.

### 6.2 이상유형과 조치 매핑

| 이상유형 | 기본 참고값 | 조치 업체 유형 |
|---|---:|---|
| 단일 셀 핫스팟 | Delta T 10K 이상 | 유지보수·정밀진단 |
| 서브모듈 과열 | Delta T 10K 이상 | 유지보수·모듈 교체 |
| 모듈 전체 과열 | Delta T 10K 이상 | 유지보수 |
| 스트링 전체 이상 | 별도 패턴 판정 | 전기공사업 가능 유지보수 |
| 접속함·인버터 과열 | Delta T 10K 이상 | 긴급·화재위험 유지보수 |
| 표면 오염·음영 | Delta T 5K 내외 | 청소·수목 정리 |

이 값은 초기 참고값이며 최종 심각도는 합의된 기준과 전문가 판정으로 확정한다. 시스템에는 임계값, 판정 근거, 규칙/모델 판본과 전문가 변경 이력을 남긴다.

## 7. 계산 엔진

### 7.1 기대발전량

```text
기대발전량(kWh/년) = 설치용량(kWp) x 일평균 발전시간(h) x 365 x 열화보정계수
열화보정계수 = (1 - 연간열화율) ^ 경과연수
```

초기 기본값은 일평균 발전시간 3.6시간, 연간열화율 0.6%, 방위·경사 보정 1.00으로 두되 모두 관리자 설정으로 관리한다.

### 7.2 성능·손실

```text
성능비 = 실발전량 / 기대발전량
손실량 = 기대발전량 - 실발전량
손실금액 = 손실량 x 적용단가
연간 기대수익 = 기대발전량 x 적용단가
```

실발전량과 기대발전량의 분석기간·단위를 같게 맞춘다. 기본 PR 구간은 0.85 이상 정상, 0.70 이상 0.85 미만 주의, 0.70 미만 점검 필요로 두며 경계값을 설정에서 수정한다. 실제발전량이 기대발전량을 넘는 경우의 손실 표시·상한·반올림 규칙은 상세 설계에서 확정한다.

### 7.3 단가·개선 효과

- 자가소비형은 계약종별·누진 구간에 따른 절감단가를 적용한다.
- 발전사업형은 `SMP + (REC 단가 x 가중치)`를 적용한다.
- 회수가능액은 `손실금액 x 이상유형별 개선가능비율`로 계산한다.
- 투자회수기간은 `예상 수리비 / 회수가능액`으로 계산한다.

기본 개선가능비율은 표면 오염·음영 0.90, 스트링 단선 0.95, 인버터 고장 1.00, 바이패스 다이오드 고장 0.70, 셀 균열·PID 0.40이다. 모든 값에 유효기간, 변경자와 변경 이유를 기록한다. 고객 리포트에는 금액이 추정치이며 실제와 다를 수 있음을 표시한다.

## 8. AI 활용과 대체 경로

| 영역 | 초기 설계 | 안전장치·대체 경로 |
|---|---|---|
| 열화상 이상 후보 | Claude API 또는 합의한 모델이 유형 후보와 신뢰도 제시 | 방사온도·규칙 결과와 분리 저장, 관리자 확정 필수, AI 실패 시 수동 태깅 |
| 리포트 문장 | 계산·진단 데이터를 고객용 설명문으로 변환 | 금액·수치는 계산 엔진 값만 사용, 관리자 편집·승인 |
| 고지서 판독 | 사용량, 요금, 계약종별 후보 추출 | 원본 위치와 신뢰도 표시, 실패·저신뢰 시 수동 입력 |
| 고객 문의 | 일반 사용법·FAQ 안내 | 수리 필요 여부와 안전 판단은 답변하지 않고 담당자 연결 |

모델 요청·응답에는 개인정보를 최소화하고 서버에서만 API 키를 사용한다. 모델명·프롬프트 판본·입력 식별자·응답·관리자 확정을 추적하되 비밀값과 불필요한 원본 전체를 로그에 남기지 않는다.

## 9. MVP와 2차 개발 경계

### 9.1 본 계약 MVP

- 이미지 업로드, 촬영 유효성 판정, 수동 태깅과 AI 후보 제시
- PR, 손실금액과 투자회수기간 계산
- 설비 등록, 무료 간이 진단, 리포트 조회·PDF, 견적 요청·비교, 마이페이지
- 업체 데이터베이스, 수동 견적 요청·회신 관리와 수수료 계산
- 관리자 설정값 관리, 승인·발행 이력과 역할별 접근 통제

### 9.2 2차 이후

- 자동 모듈 인식·정렬과 오소모자이크 생성
- 기상 API 자동 연동과 시계열 추세 예측
- 네이티브 모바일 앱과 실시간 발전량 모니터링
- 업체 전용 포털과 자동 입찰
- 수리 전후 발전량 기반 예측·실제 회수액 비교 고도화

## 10. 배포·호환성 기준

초기 기준선은 다음과 같다.

- GitHub: 발주처가 인수할 소스·문서·변경 이력의 기준
- Cloudflare: 웹 프론트엔드, 도메인·DNS와 엣지 배포 후보
- Supabase: Auth, PostgreSQL, 비공개 Storage와 짧은 서버 작업
- 별도 이미지 작업 서버: 방사온도 원본 파서, 제조사 SDK, 장시간 이미지 처리와 PDF 생성
- Claude API: 서버 측 AI 어댑터로 연결하고 발주처 계정·비용을 사용

Cloudflare·Supabase 고유 호출은 어댑터에 모으고 핵심 계산·업무 규칙과 분리한다. PostgreSQL 변경 이력, Storage manifest·체크섬, 환경변수 목록, 컨테이너 실행 정의와 백업·복원 절차를 유지해 다른 호스트로 이전할 수 있게 한다. 데모 단계에서는 비용이 발생하지 않는 범위를 유지하고, 실제 고객 자료를 받기 전에 운영 플랜과 비용 한도를 발주처가 승인한다.

## 11. 보안·개인정보 기준

- 관리자·고객·업체의 화면과 데이터 권한을 분리한다.
- 설비 등록 시 개인정보 수집·이용 동의를 받고 동의 문서 판본과 시점을 저장한다.
- 개인정보처리방침·이용약관 초안을 제공하되 최종 문구와 운영 책임은 발주처 승인을 받는다.
- HTTPS를 사용하고 비공개 파일은 권한 확인 후 짧은 수명의 링크로 제공한다.
- 주소, 사용량, 연락처 등 민감도 높은 필드의 저장 암호화 범위와 키 소유자를 상세 설계에서 확정한다.
- 인접 건물·차량 번호판 등 제3자 식별정보가 있는 이미지는 제한된 임시 구역에서 마스킹·검수한 후 고객·업체가 보는 보존본으로 전환한다.
- 원본 보존이 필요한 경우 접근자를 최소화하고 보존기간·파기와 분쟁 대응 근거를 발주처와 확정한다.

## 12. 산출물과 12주 일정

### 12.1 산출물

6. 오픈소스·기존 보유 라이브러리와 외부 서비스 라이선스 명세

| 3-6주 | 관리자 기능 | A-1부터 A-6까지의 핵심 입력·검수·설정·리포트 흐름 |

## 13. 검수 시나리오

실제 또는 발주처가 승인한 대표 데이터 3건으로 다음 흐름을 각각 완료한다.

`설비 등록 → 점검 데이터 업로드 → 유효성 판정 → AI 이상 후보 확인 → 관리자 확정 → 리포트 자동 생성 → 승인·발행 → 고객 조회·PDF 다운로드 → 견적 요청 → 업체 3곳 회신 → 비교·선택 → 수수료 산정`

검수 기록에는 사용 계정·역할, 입력 파일, 설정 판본, 모델/규칙 판본, 계산 결과, 승인 이력과 화면·결과 증거를 포함한다. 외부 업체의 실제 회신을 사용하는지 검수용 업체 계정을 사용하는지는 착수 시 확정하되, 시스템 안에서는 3개 회신의 전체 흐름이 재현돼야 한다.

## 15. 구현 전 필요한 자료

- 지원 카메라 제조사·모델·펌웨어와 방사온도 원본 샘플
- 정상, 이상, 경계 사례가 포함된 열화상·가시광 대응 묶음 3건 이상
- 촬영 조건 기록표와 설비 행·열 또는 위치 식별 방식
- 인버터 계측값 또는 발전량 입력 예시와 전기요금 고지서 예시
- 기존 고객용 보고서와 폐패널 재활용 인증서 예시
- 업체 유형·면허·가용지역·평점·견적 회신 샘플
- 실제 역할, 승인자, 데이터 보존기간과 개인정보 마스킹 운영 절차

이 자료가 늦어지면 해당 기능을 임의 데이터로 확정하지 않고 수동 입력·검수 경로를 먼저 완성한다.
