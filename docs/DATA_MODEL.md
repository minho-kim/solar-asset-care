# 개념 데이터 모델

- 상태: 계약 전 준비 초안
- 작성일: 2026-08-25
- 주의: 이 문서는 계약 및 요구사항 확정 전 개념 모델이다. 실제 테이블명, 컬럼명, 상태값, SQL과 API 형식은 정의하지 않는다.

## 1. 확인된 내용

- 고객사·발전소·설비·검사·이미지·분석·전문가 판정·보고서·유지보수 결과가 서로 연결돼야 한다.
- 인버터에서 모듈까지의 연결 구조가 있어야 발전 데이터와 열화상 위치를 의미 있게 비교할 수 있다.
- 원본 파일은 미리보기·분석 파생 파일과 분리하고 체크섬·이력을 보존해야 한다.
- 자동 분석 후보와 전문가 최종 판정은 서로 다른 기록으로 유지해야 한다.
- 보고서의 초안·승인·발행·개정과 전문가 수정 이력을 추적해야 한다.
- 여러 고객 조직을 지원할 수 있으므로 업무 데이터와 파일의 조직 소속을 명확히 해야 한다.

## 2. 계약 전 기술 제안

### 2.1 개념 영역

#### 조직과 접근

- **조직**: 데이터를 소유하거나 서비스를 운영하는 고객·운영 단위다.
- **사용자**: 로그인 가능한 사람이다.
- **조직 멤버십**: 사용자가 어느 조직에서 어떤 역할과 유효기간으로 활동하는지 표현한다.
- **역할/권한**: 조회, 업로드, 진단, 승인, 발행과 유지보수 처리 범위를 표현한다.

한 사용자가 여러 조직과 관계를 가질 가능성은 열어 두되, 현재 선택 화면만으로 권한을 결정하지 않고 서버에서 각 요청의 조직 소속과 권한을 검증하는 방향을 제안한다.

#### 고객 자산

- **고객사**: 계약·연락·보고서 수신의 업무 주체다. 운영 조직과 고객사의 관계가 같은지 다른지는 확인이 필요하다.
- **발전소**: 검사와 보고서가 귀속되는 물리적 자산 단위다.
- **설비**: 인버터, MPPT, 스트링, 모듈과 기타 검사 대상의 개념적 자산이다.
- **설비 연결 관계**: 상위·하위 설비와 유효 기간을 연결한다. 장비 교체와 재배선을 과거 검사에 소급 적용하지 않도록 시점 개념이 필요하다.
- **촬영/설비 위치 기준**: 현장 도면, 행/열, 자산 라벨, 좌표 등 촬영 위치를 실제 설비에 연결하는 기준이다.

#### 검사와 촬영

- **검사 요청**: 목적, 대상, 일정과 담당 업무를 묶는 단위다.
- **현장 방문/촬영 묶음**: 한 번의 촬영 실행과 그 조건을 표현한다.
- **촬영 조건**: 카메라, 시간, 거리·각도, 날씨·일사량 등 진단 해석에 필요한 맥락이다.
- **파일 자산**: 업로드된 원본 또는 생성된 파생물이다. 종류, 소속, 무결성, 생성 경로와 보존 책임을 구분한다.
- **이미지 짝 관계**: 열화상과 가시광 사이의 후보/확정 관계, 매칭 근거와 사람의 수정 이력을 표현한다.

#### 분석과 전문가 판정

- **분석 실행**: 어떤 입력과 처리 버전으로 언제 수행됐는지 표현하는 재현 단위다.
- **분석 후보**: 자동 처리에서 발견한 온도 이상·고장 의심 영역과 신뢰도·근거의 후보 정보다.
- **주석**: 이미지 위 점·영역·텍스트와 작성 주체를 표현한다.
- **전문가 검토**: 담당 전문가, 검토 범위, 완료/반려와 수정 이력을 표현한다.
- **최종 진단**: 전문가가 확정한 판단, 근거, 불확실성과 심각도/우선순위 개념이다.
- **조치 권고**: 진단에 대응하는 점검·교체·모니터링 등의 권고와 기한 후보를 표현한다.

분석 후보를 수정했다고 해서 원래 후보를 덮어쓰지 않는다. 전문가가 후보를 채택·수정·기각한 관계를 남기는 편이 모델 개선 평가와 감사에 유리하다.

#### 보고서

- **보고서**: 한 검사 또는 합의된 검사 묶음에 대한 고객 전달 문서의 논리 단위다.
- **보고서 판본**: 초안·검토본·발행본·개정본처럼 내용이 고정된 판본이다.
- **승인 기록**: 승인/수정 요청의 주체, 시점과 사유다.
- **발행 기록**: 고객에게 공개된 판본, 공개 시점, 회수/대체 관계와 알림 결과다.

고객이 보는 ‘최신 보고서’와 법적·감사 목적의 과거 발행본을 구분한다. 발행 파일을 같은 경로에서 덮어쓰는 방식을 피한다.

#### 유지보수

- **유지보수 요청**: 하나 이상의 조치 권고를 후속 업무로 전환한 단위다.
- **사업자/담당 관계**: 요청을 처리할 내부 담당 또는 외부 사업자와 공개 범위를 표현한다.
- **견적/작업 계획**: 계약 범위에 포함될 경우 제안 비용·일정·범위의 판본을 표현한다.
- **작업 기록**: 실제 수행 내용, 시점과 담당을 표현한다.
- **완료 증빙**: 조치 전·후 사진, 확인 의견과 완료/부분 완료 근거다.

진단 결과의 변경과 유지보수 진행의 변경은 별도 수명주기로 관리한다.

#### 운영 지원

- **알림**: 사건, 수신자, 채널과 전송 결과를 표현한다.
- **감사 기록**: 누가 어떤 중요 대상을 조회·변경·승인·발행했는지 추적한다.
- **내보내기 작업**: 요청 범위, 생성 파일, 만료와 다운로드 권한을 표현한다.
- **보존/삭제 요청**: 계약과 법적 요구에 따른 보존, 파기, 예외 보류를 표현한다.

### 2.2 핵심 관계

```text
조직 ──< 조직 멤버십 >── 사용자
  │
  └──< 고객사 ──< 발전소 ──< 설비 ──< 설비 연결 관계
                         │
                         └──< 검사 요청 ──< 촬영 묶음 ──< 파일 자산
                                                     │         │
                                                     │         ├──< 이미지 짝 관계
                                                     │         └──< 분석 실행 ──< 분석 후보
                                                     │                              │
                                                     └──< 전문가 검토 ──< 최종 진단 ──< 조치 권고
                                                                                         │
검사 요청 ──< 보고서 ──< 보고서 판본 ──< 승인/발행 기록                           └──< 유지보수 요청
                                                                                              └──< 작업·완료 증빙
```

이 그림은 논리 관계다. 저장 기술과 실제 cardinality는 업무 사례를 확인한 뒤 결정한다.

### 2.3 무결성 원칙

- 모든 업무 대상은 소유 조직과 접근 맥락이 명확해야 한다.
- 원본은 업로드 완료 후 내용 변경 대신 새 제출 또는 명시적 무효 처리를 사용한다.
- 체크섬은 전송 완전성·중복 후보 판단에 사용하되 동일 체크섬의 의미를 업무적으로 확인한다.
- 파생물은 사용한 원본과 처리 실행을 역추적할 수 있어야 한다.
- 전문가 판정은 작성자, 수정자, 사유와 승인 관계를 보존한다.
- 발행 보고서는 사용한 진단·이미지·템플릿 판본을 재현 가능하게 연결한다.
- 설비 연결 변경은 유효 시점을 남겨 과거 검사 해석이 바뀌지 않게 한다.
- 삭제는 권한·보존 정책·발행 책임을 확인하며 감사 기록까지 임의로 제거하지 않는다.

### 2.4 수명주기 제안

- **검사**: 요청 → 정보 보완 → 촬영/업로드 → 품질 확인 → 전문가 검토 → 보고서 처리 → 후속 조치/종결
- **파일**: 업로드 중 → 무결성 확인 → 사용 가능 또는 검토 필요 → 보존/파기 대상
- **분석**: 대기 → 실행 → 성공/실패 → 재실행 또는 사용 승인
- **보고서**: 초안 → 검토 → 승인 → 발행 → 개정/회수
- **유지보수**: 요청 → 범위 확인 → 계획/견적 → 수행 → 완료 확인 또는 보류/취소

이는 설명용 수명주기이며 실제 상태값 목록이 아니다.

## 3. 추가 확인이 필요한 내용

- 운영 조직, 고객사, 유지보수 사업자의 법적·데이터 소유 관계
- 한 발전소를 여러 고객사가 공동 관리하거나 소유할 수 있는지
- 설비 식별 표준, 기존 자산대장과 장비 교체·재배선 이력의 존재 여부
- 촬영 위치를 모듈까지 연결할 기준과 위치 정확도
- 한 이미지에 여러 설비가 포함되거나 한 설비가 여러 이미지에 걸치는 경우
- 검사·진단·보고서가 1:1인지, 여러 검사를 한 보고서로 묶는지
- 전문가 공동 검토, 2차 검토와 의견 불일치 처리
- 보고서의 승인 서명, 회수, 과거 판본 열람과 법적 보존
- 유지보수 견적·작업의 여러 사업자 비교와 고객 승인 포함 여부
- 개인정보·시설 보안 정보의 분류와 보존/삭제 기간
- 시계열 인버터 데이터 양과 파티셔닝·집계 필요성

## 4. 계약 후 상세 설계 전 확인물

- 열화상·가시광 원본 샘플과 메타데이터 추출 결과
- 기존 설비 자산대장과 연결도 예시
- 기존 보고서, 전문가 판정 양식과 개정 사례
- 역할별 실제 업무 사례 3~5건
- 인버터 공식 API 문서와 샘플 응답(연동 범위에 포함할 경우)
